# ポジション・リスク管理(PositionSheet.xlsm、叩き台)

会社のポジション・リスクを貼り付けて、米金利のデスクで標準的なやり方(テナー別デルタ、PCAの
ファクター・リスク、フォワードのリスク、日中の損益の説明)で見るためのブック。2026-10-25に
叩き台として作成した。使いながら、ユーザーと相談して詳細を決める(このページの「未決定」)。

コード: `engine/position/`(`common/`だけに依存)、`PositionSheet.py`(再エクスポート)。
テスト: `tests/test_position.py`。

## 方針(ユーザーと決定)

- 会社のリスク(デルタ・ガンマ・ベガ)は計算後の値を入力シートに**貼り付ける**(会社のデータの変換は
  後で実装する)。現物だけは銘柄ごとのポジションが来るので、こちらでリスクを計算する。
- グリッドは全ピラー(Setupシートの34本)。現物とスワップを別々に見て、足したネットも出す
  (現物はASWにしない)。
- こちらでリスクを計算するのは、**日中の新規取引**と**現物**だけ。SODのデリバティブのリスクは会社の値をそのまま使う。
- VBAのボタン(データの取得・計算の開始)は作ってよいが、重い計算はVBAにさせない(Python)。
  叩き台では貼り付けの運用なのでVBAは使っていない(Import Functionsが作るUDFのラッパーだけ)。
- 会社のデータは**コミットしない**。入力シート(Delta・Gamma・Vega・Bonds・Trades・Others)の5行目以降は
  `tools/template.py`の`RECEIVE_AREAS`で値を消し、雛形には数式だけが残る。

## 米金利デスクの標準的なやり方(叩き台に入れたもの)

調べた結果と、それをどこに入れたか。

1. **テナー別デルタのグリッド**(bucketed DV01): カーブの各ピラーを1本ずつ動かしたPVの変化。
   スワップの帳簿を満期ごとに合算して見る。合計がパラレルのDV01。→ `Grid`シート(+バケット別の集計、
   大きい順の5本、ヒートマップ)。
2. **現物をスワップのグリッドに写す**: 債券を、OISのカーブに対するZスプレッド(一定)で評価し、同じピラー・
   同じバンプでデルタを測る(キーレート・デルタ)。スワップのグリッドとそのまま足せる。→ `Bonds`シート。
3. **PCAのファクター・リスク**: パーレートの**日次変化**(bp)の**分散共分散行列**を固有値分解する
   (相関行列ではない)。PC1〜PC3が水準・傾き・曲率。デルタのベクトル d を各主成分 L_k に射影して
   - エクスポージャー E_k = L_kᵀ d(ファクターが1bp動いたときの損益)
   - 1σの損益 = E_k × √λ_k(ファクターの日次の標準偏差)。どのファクターのリスクが大きいかを同じ物差しで比べる
   - 全体のσ = √(Σ_k (E_k √λ_k)²)、上位k本の外側を**残差リスク**(カーブの局所的な歪みへのエクスポージャー)とする
   - 残差のデルタ = d − L_k L_kᵀ d(ピラーごと)
   → `PCA`シート。
4. **PCA中立のヘッジ**: 3本のピラーで、PC1〜PC3のエクスポージャーが0になるDV01を解く
   (h = (L_hᵀ)⁻¹(−E))。単純なデルタ中立やDV01比のフライと違い、水準・傾きの影響が残らない。→ `PCA`シート。
5. **ファクターのショックのシナリオ**: ±1σ・±2σの損益(デルタ+½ガンマ)。→ `PCA`シート。
6. **フォワードのリスク**: 隣り合うピラーの満期の間(区間)のフォワードを1bp動かしたときのデルタ。
   パーのデルタからヤコビアン J で換算する(フォワードのデルタ = Jᵀ d)。→ `Forward`シート。
7. **日中の損益の説明**(P&L explain): 前日引けからのレートの変化 Δr で
   デルタ損益 Σ d·Δr、ガンマ損益 ½ ΔrᵀΓΔr、ベガ損益 Σ ν·Δσ、キャリー(Others)、日中の取引のPV。
   デルタ損益をファクターの動き(f = LᵀΔr)に分解し、今日の動きが何σかも見る。今のデルタ ≈ SODのデルタ + ΓΔr。→ `Live`シート。
8. **グリッドに乗らないリスク**(Others): ベーシス、キャリー、フィキシング、現物オプションのベガ、先物など。→ `Others`シート。

参考: Huggins & Schaller『Fixed Income Relative Value Analysis』(PCA・PCAで重みを付けたヘッジ)、
FRMの教材(非パラレルのシフト、PCAによるヘッジ)。ガンマ・ベガのグリッドの形(ピラー×ピラー、
満期×原資産)は一般的な形に合わせたもので、会社の定義はひな形を見て確認する。

## ブックの構成

| シート | 中身 |
|---|---|
| Main | 要約(デルタの合計、PCAの1σ、日中の損益)とグラフ4枚 |
| Grid | ピラー×(デリバティブSOD・日中の取引・スワップ計・現物・ネット・What-if)、バケット別、大きい順 |
| PCA | ファクターごとの1σ(スワップ計・現物・ネット・What-if込み)、残差、ヘッジ、シナリオ、主成分ベクトルのグラフ |
| Forward | 区間ごとのフォワードのデルタ(右側にJ) |
| Live | 前日引け→ライブのレートの変化、損益の説明、ファクター別、今のデルタ、volの変化 |
| Delta / Gamma / Vega | 会社のリスクの貼り付け先(Gammaは対角の列とピラー×ピラーの行列のどちらか) |
| Bonds | 現物のポジション(銘柄コード・額面)と、UDFが返す行ごとのリスク |
| Trades | 日中の取引(Done=約定済み、What-if=検討中) |
| Others | グリッドに乗らないリスク |
| Setup | 評価日・リスクの基準日・PCAの設定、ピラー(カーブ・PCAに使うか、バケット)、ライブのレート |

単位はすべて百万円、デルタは「金利が1bp上がったときのPVの変化」(現物のロング・レシーブはマイナス)。

## UDF(`engine/position/udf.py`)

QuantLib・固有値分解・DBの読み出しだけ。合計・射影・換算・損益の説明はExcelの数式(SUM・MMULT・MINVERSE、
名前付きのLAMBDA `POS_PcExp`・`POS_PcSigma`)。

| UDF | 中身 |
|---|---|
| `PosBondRisk` | 現物の行ごとのリスク(Zスプレッド固定のキーレート・デルタ。単利はDBの引け値かoverride) |
| `PosTradeRisk` | 日中の取引(標準のOIS)の行ごとのリスク(`risk.bucketed_deltas`) |
| `PosForwardJacobian` | パー→フォワードの換算行列 J |
| `PosPcaLoadings` / `PosPcaEigen` / `PosPcaWindow` | ピラーの日次変化の分散共分散のPCA(`engine/common/pca.py`を使う) |
| `PosCloseRates` / `PosCloseVols` | DBのその日の引け値(損益の説明の基準) |

PCAの推定(`engine/common/pca.py`・`history.py`)は、SwapAnalysisと共有するため`engine/pca/`から`common/`へ移した。

UDFの実体は次の3つのモジュール(`udf.py`はExcelの範囲を型に直して呼ぶだけ)。

| モジュール | 中身 |
|---|---|
| `bonds.py` | 現物の行ごとのリスク(`bond_risks`)。単利からスポット受渡(T+1)の単価を出し、OISの基準カーブに対するZスプレッド(連続複利で一定)を解いて、ピラーを1本ずつ動かしたカーブ(`market.CurveSet.bumped`)で単価を出し直す。JGBの規約は`engine/common/bond.py` |
| `trades.py` | 日中の取引の行ごとのリスク(`trade_risks`)。規約は標準のOIS(`terms.STANDARD`)、起算日は空欄=スポット・日付・期間(スポットからの先日付)、期間はtenorか満期日。デルタは`risk.bucketed_deltas` |
| `forward.py` | パー→フォワードの換算行列 J(`forward_jacobian`)。作り方は下の「フォワードの換算行列の作り方」 |

### フォワードの換算行列の作り方

基準カーブの暦日ごとのDFで`ql.DiscountCurve`を作り、区間 [a, b] にかかる日のDFに exp(−1bp×区間内の年数) を
掛けたカーブとで、各ピラーのパーレート(`swap_pricer.par_rate`)の差を取る。基準のパーレートも同じ暦日の
カーブで出す(補間の差が換算に入らないように)。O/Nはスポットより前の1日なので、自分自身の区間(J=1)だけにする。
各行の和はほぼ1(フォワードが連続複利、パーが年1回の複利なので1から1〜2%ずれる)。

## 前提・注意

- 会社のデルタの定義(パーかゼロか、バンプ幅、符号、単位)とピラーは、ひな形で確認する。日中の取引・現物の
  デルタ(こちらの計算)は、パーのピラーを0.1bp動かして1bpあたりにしたもの(PricingSheetのRiskGridと同じ)。
- ガンマの定義は「1bp動いたときのデルタの変化」と仮定した(損益 = ½ΣΓΔrΔr)。
- PCAに使うピラーはSetupのPCAの列で選ぶ。O/N(翌営業日に公表)と1W(DBに欠けがある)は既定で外しており、
  そのデルタはファクターに乗らない(PCAのシートの合計にも入らない)。
- 現物のリスクは評価日(空欄=ライブ)のカーブで計算する(SODの会社のリスクと時点が違う)。現物の価格は
  DBの引け値(ライブの価格はまだない)。
- 日中の損益の説明は、SODのデリバティブ(会社のデルタ・ガンマ・ベガ)+現物のデルタ×レートの変化。
  日中の取引は損益の説明に入れず、PVで足す。
